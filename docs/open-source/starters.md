# Starters and Examples

Starter repos help people reach a first success quickly.

## Purpose

- Reduce time-to-first-integration.
- Show the supported patterns in a working form.
- Provide copies for common use cases.

## Starter types

- Payment link starter
- Invoice starter
- Social payments starter
- MCP agent starter
- SDK quickstart starter
- Treasury/reporting starter

## Core features

- Minimal setup.
- Clear environment variables.
- Sample data.
- Deployment instructions.
- Tests or verification scripts.

## Implementation scope

- Each starter should map to one real Corridor workflow.
- Examples should stay current with the canonical API contract.
- The starter repo should not hide essential steps behind magic.

## What good starters do

- Show a complete happy path.
- Include a failure case.
- Document where the sample ends and the production code begins.
